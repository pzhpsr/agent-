# LangChain 七天学习计划

周期：2026-11-04 至 2026-11-10；每天 3–4 小时。

目标：围绕规划、工具调用、多 Agent、系统对接、RAG 和评测学习；理解优先，最终组合最小助手。

| 天 | 知识点 | 练习与验收 |
|---|---|---|
| D1 | LangChain 消息、模型与工具循环 | 实际调用计算工具；解释模型请求、函数执行与结果回传 |
| D2 | 工具封装及 API/SQLite/文档 | 三种工具分别独立调用并接入 Agent；验证错误与空结果 |
| D3 | 规划、步骤依赖与自动化 | 同一任务直接执行与先规划执行对照；一步失败后明确停止 |
| D4 | RAG：分块、嵌入、检索与回答 | 查询 5–10 篇教学文档，展示检索片段并引用来源；无证据时拒绝编造 |
| D5 | 多 Agent 角色、交接与复核 | 资料助手与检查助手协作，最多修订一次；比较单 Agent |
| D6 | 评测、失败分类与迭代 | 12 道题（8 道开发、4 道保留），同题比较一次修改前后 |
| D7 | 综合与迁移 | 组合最小助手；用户亲自增加工具或更新文档，定位预设故障 |

每日节奏：讲解与运行约 45 分钟、亲手修改约 90 分钟、验证排错约 45 分钟，剩余时间复盘。

掌握标准：能解释执行过程，在提示下修改关键逻辑并验证，初步定位错误。
不以课程代码准备好替代用户实际完成；不增加网页界面、云部署或完整企业业务系统。

环境：独立 Python 3.12 环境；现有共享 .env；LangChain 当前稳定发行版安装后锁定。
本地 SQLite、教学 Markdown、sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2 CPU 嵌入、LangChain 内存向量存储。

每任务模型调用上限 8 次；接口重试默认关闭；Agent 协作最多修订一次。
先小规模验证，不充值、不展开大型评测；API、不支持工具、模型下载等失败均如实记录。

验收情景：工具参数错误、API 超时、数据库空结果、文档缺失、步骤失败、RAG 无答案/相近文档、多 Agent 上下文和停止条件。
交付：讲义、可运行代码、教学数据、配置示例、依赖锁定、README、必要验证记录。
