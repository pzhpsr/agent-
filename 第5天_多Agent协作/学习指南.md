# D5：两个 Agent 如何交接与复核

```powershell
Set-Location 'H:/论文学习/agent/xuexi'
```

代码在上一层的 `xuexi_lab/`，下面提到的路径均相对于课程根目录。

目标：理解多 Agent 协作的职责和代价，而不是只给两次模型请求起不同名字。

## 1. 运行基线（约 35 分钟）

```powershell
./.venv/Scripts/python.exe -X utf8 -m xuexi_lab run --mode rag --question '报销材料不完整时如何处理？引用知识库文档。'
./.venv/Scripts/python.exe -X utf8 -m xuexi_lab day5
```

第一条是单 Agent；第二条是两个独立的 LangChain Agent：资料助手可调用工具，检查助手不具备工具，仅核对交接的证据。
检查不通过时允许资料助手修订一次，再检查一次；仍失败明确为 review_failed。
两位 Agent 的所有模型请求共用同一份最多 8 次的预算。

## 2. 看交接内容（约 35 分钟）

在 trace 找 researcher、reviewer、review，必要时出现 researcher_revision。
检查助手接收原问题、草稿、工具请求和实际返回值，不接收密钥或原始请求头。
它输出 `{approved, feedback}`。这个意见仍是模型判断，不是真值，最终需要人工核对。

与“一个 Agent 调多个工具”的区别：职责、工具权限、上下文和复核输出都被分开。
两个 Agent 可以使用同一个基础模型，不要求两个 API key。

## 3. 亲手修改（约 60 分钟）

只修改 reviewer 的附加说明，要求逐条检查：数字是否来自工具、引用是否支持结论、是否声称未实际执行的操作。
保持 JSON 输出字段不变，用相同问题运行，检查 feedback 是否更具体。
记录是否真的改善了错误检测，同时比较多出来的调用和耗时。

## 4. 两个边界（约 35 分钟）

```powershell
./.venv/Scripts/python.exe -X utf8 -m xuexi_lab day5 --max-calls 2
./.venv/Scripts/python.exe -X utf8 -m xuexi_lab day5 --question '知识库是否承诺工单两小时内解决？没有就明确说未提供，不要承诺。'
```

调用预算不足应停止，不能绕过限制偷偷增加请求。知识库没有承诺时两位 Agent 都不应补编。

## 5. 验收

解释两个 Agent 的输入、输出、权限与交接内容，指出协作在哪些题上有收益、哪些题上只增加开销。
不能因为 reviewer 输出 approved 就把不真实的答案标为正确。
