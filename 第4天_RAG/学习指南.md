# D4：从文档到有依据的 RAG 回答

[课程首页](../README.md) · [当天学习笔记](学习笔记.md) · [学习进度](../学习进度.md)

本页所有命令都在课程根目录执行，先运行：

```powershell
Set-Location 'H:/论文学习/agent/xuexi'
```

代码在上一层的 `xuexi_lab/`，下面提到的路径均相对于课程根目录。

目标：亲手看到检索增强生成（Retrieval-Augmented Generation，RAG）的每一步。

```text
原文 → 分块 → 嵌入向量 → 内存向量存储
问题 → 查询向量 → 相似片段 → 作为数据交给模型 → 回答＋引用
```

## 1. 先验证检索，再调用模型（约 50 分钟）

```powershell
./.venv/Scripts/python.exe -X utf8 -m xuexi_lab rag-build
./.venv/Scripts/python.exe -X utf8 -m xuexi_lab search --query '投影仪最多借用几天' --k 3
./.venv/Scripts/python.exe -X utf8 -m xuexi_lab day4
```

首次会下载本地多语言模型，使用已有 PyTorch 的 CPU 路径，不使用付费嵌入 API。
模型下载失败与对话 API 失败是两类问题；不能把前者误判为密钥无效。
`search` 只做本地语义检索，没有调用对话模型。

## 2. 阅读一段真正的证据（约 30 分钟）

返回值中 `source` 是文档名、`chunk` 是片段编号、`score` 是相似度排序依据、`text` 是原文。
检查其中是否确有“最长连续借用 3 天”。答对数字但引用了无关文档，仍不算证据完整。

相似度不是概率，更不是答案正确率。检索总会返回最相似的一些片段，它们可能都不能回答问题。

## 3. 亲手修改一个因素（约 60 分钟）

在 `rag.py` 中将 `KnowledgeBase` 默认 `chunk_size` 从 240 改为 120，保持 overlap=40 和问题不变。
比较分块数量、实际命中的原文及最终回答。不要同时修改 k，否则无法归因。
之后恢复基线，再只用 `search --k 1` 与 `--k 3` 比较。

## 4. 无答案与文档更新（约 45 分钟）

```powershell
./.venv/Scripts/python.exe -X utf8 -m xuexi_lab day4 --question '根据知识库，投影仪采购价是多少？无依据时回答知识库未提供。'
```

预期明确没有采购价依据。若出现数字，先读检索片段，再判断是检索错还是模型补编。
用自己的话新增一份 `data/knowledge/07_课程安排.md`，写入两个明确事实，再运行 search 查询。
检查 fingerprint 改变、来源出现新文件。进程每次重建索引，内容没变化的嵌入走缓存。

## 5. 验收

解释分块、嵌入、向量存储、检索和生成各自负责什么；指出一次检索错误与一次回答错误的区别。
给出一个有依据答案、一个无依据回答，以及你修改分块后的真实对照。
选读：All-in-RAG 的数据加载、文本分块、向量嵌入和四步构建 RAG。
