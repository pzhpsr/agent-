# D6：用固定题证明改进

[课程首页](../README.md) · [当天学习笔记](学习笔记.md) · [学习进度](../学习进度.md)

本页所有命令都在课程根目录执行，先运行：

```powershell
Set-Location 'H:/论文学习/agent/xuexi'
```

代码在上一层的 `xuexi_lab/`，下面提到的路径均相对于课程根目录。

目标：把“看起来更好”变成可核对的证据，区分程序断言、模型评分和人工结论。

## 1. 预览与小规模运行（约 35 分钟）

```powershell
./.venv/Scripts/python.exe -X utf8 -m xuexi_lab eval --preview --split dev
./.venv/Scripts/python.exe -X utf8 -m xuexi_lab day6 --limit 2
```

固定题共 12 道：8 道开发题，4 道保留题；覆盖工具、数据库、RAG、规划和协作。
预览不调用模型。完整运行前确认小规模记录正确，复用现有接口，不充值或盲目扩大评测。

## 2. 建立基线（约 40 分钟）

```powershell
./.venv/Scripts/python.exe -X utf8 -m xuexi_lab eval --split dev --limit 8 --variant baseline
```

记录实际输出的 JSON 路径。逐题读 trace，将失败分成配置/网络、选工具、参数、检索、计算、引用、协作停止等类别。
统计任务完成、工具是否调用、结果正确性、耗时、服务提供的用量；未知用量不能填 0。

## 3. 只改一个因素（约 60 分钟）

课程内置 `evidence_first` 只增加一段“先核对证据再回答”的提示词；模型、工具、数据和题目不变。

```powershell
./.venv/Scripts/python.exe -X utf8 -m xuexi_lab eval --split dev --limit 8 --variant evidence_first
./.venv/Scripts/python.exe -X utf8 -m xuexi_lab compare --before '基线实际JSON路径' --after '修改后实际JSON路径'
```

对照拒绝不同题目、数据文件或模型配置的混比。若你之前修改了工具或分块，先固定本次实验使用的版本，并在笔记注明。
如果效果没提升，记录这个结论；不能删掉失败题制造准确率上升。

## 4. 你必须人工核对（约 40 分钟）

自动 `auto_pass` 检查完成状态、必要工具、阶段和答案片段；它无法证明语义完整或引用充分。
在结果副本或笔记中逐题记录人工正确/错误及依据，不要把 pending 直接改成通过而不读证据。
评测题中的必要字符串可能产生假阴性，发现时记录人工裁决及原因，不随意改题追求高分。

## 5. 保留题与验收

先定下最终方案，再运行：

```powershell
./.venv/Scripts/python.exe -X utf8 -m xuexi_lab eval --split holdout --limit 4 --variant evidence_first
```

不要根据这 4 道题继续反复调参后还把它称为未见测试。
交付一张小表：基线/修改后自动通过数、人工正确数、主要失败类型、调用和耗时。
本课程不要求额外安装 Ragas；理解基本评测后可以选读它的指标与案例，再判断是否有必要引入。
