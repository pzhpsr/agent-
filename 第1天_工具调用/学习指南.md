## 1. 先建立直觉（约 25 分钟）

```text
问题 → 模型读取问题和工具描述
            ↓ 返回工具名和参数
       LangChain 调用本地函数
            ↓ 得到真实返回值
       工具结果作为消息交回模型
            ↓
          最终答复
```

模型不会凭空获得 Python 运行权限。它生成的是结构化调用请求；LangChain 在已注册工具中找到函数并执行。
`@tool` 将函数名、说明、参数类型转成模型可见的工具定义，`create_agent` 管理工具循环。

区分三种消息：HumanMessage 是用户输入，AIMessage 是模型输出（可能含 tool_calls），ToolMessage 是工具执行结果。
普通文本回答不等于调用过工具，必须看运行证据。

## 2. 先独立计算，再接入 Agent（约 35 分钟）

在 `H:/论文学习/agent/xuexi` 运行：

```powershell
./.venv/Scripts/python.exe -X utf8 -m xuexi_lab init
./.venv/Scripts/python.exe -X utf8 -m xuexi_lab tool calculate --expression '(18+24)/2'
./.venv/Scripts/python.exe -X utf8 -m xuexi_lab doctor
./.venv/Scripts/python.exe -X utf8 -m xuexi_lab day1
```

第二条命令的预期是 `ok: true` 与 `value: 21.0`，没有模型参与。
doctor 需要真实工具请求、计算结果 84、工具回传后的最终答复均通过；缺一项都不能算接口验证成功。

`day1` 输出包含 `trace_path`。把实际路径复制到下方占位处再运行：

```powershell
./.venv/Scripts/python.exe -X utf8 -m xuexi_lab trace --path '实际 trace_path'
```

依次找 `model_request`、`model_response.tool_calls`、`tool_request`、`tool_result` 和 `finish`。
第一轮模型选工具、第二轮根据结果作答，所以常见是两次模型调用，但以实际记录为准。

## 4. 你亲手做的一次修改（约 60 分钟）

先运行同一个问题：

```powershell
./.venv/Scripts/python.exe -X utf8 -m xuexi_lab day1 --question '计算 27*13，再减去51。使用工具并说明依据。'
```

只修改 `calculator` 的工具说明：补充“多步四则运算应合并为一个表达式，例如 (a*b)-c”。
保持函数名、参数、模型和问题不变，再运行一次，比较两份 trace。
预期数学结果是 300；工具调用次数是否改变要看实际模型行为，不预设优化一定有效。

## 5. 故障与验收（约 35 分钟）

```powershell
./.venv/Scripts/python.exe -X utf8 -m xuexi_lab day1 --question '调用 calculate 计算1/0，解释返回值。'
./.venv/Scripts/python.exe -X utf8 -m xuexi_lab day1 --max-calls 1
```

第一条应体现除数为零，不能编造结果；第二条工具循环若需要第二次模型调用，应以 `model_limit` 停止。
不要把达到调用上限误判为模型接口坏了。
