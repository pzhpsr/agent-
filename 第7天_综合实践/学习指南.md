本页所有命令都在课程根目录执行，先运行：

```powershell
Set-Location 'H:/论文学习/agent/xuexi'
```

代码在上一层的 `xuexi_lab/`，下面提到的路径均相对于课程根目录。

目标：把本周机制连起来，并证明你能做一次实际修改。

## 1. 运行组合任务（约 40 分钟）

```powershell
./.venv/Scripts/python.exe -X utf8 -m xuexi_lab day7
```

资料助手检索规则、查询 SQLite、调用计算工具，检查助手核对证据和结论。
预期：差旅 550.00 + 办公 140.00 = 690.00，加 10% 得到 759.00 CNY。
必须看到相关工具的真实请求和返回；答案数字正确但没有来源仍需指出缺陷。

## 2. 你独立完成一次迁移（约 75 分钟）

从以下练习中选择一个并亲自完成，不要求把两种都做完：

- 增加一个同类型工具，例如 D2 的平均支出，并让组合助手使用它。
- 增加一份教学文档或修改一条规则，重新建立索引，用新问题核对引用和事实是否随数据变化。

改规则时保留原文件副本于个人笔记或明确记录差异；固定评测仍应使用原始基线数据，不能拿变化后的规则直接比较旧成绩。

## 3. 预设故障排查（约 45 分钟）

先预测故障应该属于哪一层，再运行：

```powershell
./.venv/Scripts/python.exe -X utf8 -m xuexi_lab tool document --name 'missing.md'
./.venv/Scripts/python.exe -X utf8 -m xuexi_lab day7 --max-calls 1
```

解释文档缺失与预算不足的区别；根据 trace 指出执行停在哪里。
如果检索结果不相关，独立运行 search，先检查分块和查询，不急于改模型提示词。

## 4. 五分钟讲解（约 30 分钟）

用你自己的话讲：

1. 一个问题如何触发规划、工具、检索和复核。
2. API、数据库和文档工具各自如何封装，有什么边界。
3. 多 Agent 何时值得用，何时增加开销。
4. RAG 解决什么问题，为什么仍可能答错。
5. 你改过什么、用什么证据证明改进，哪里还不稳定。

## 5. 最终验收

运行本地测试，并检查 README 中的命令与你的环境一致。
保留必要源码、数据、依赖记录、学习笔记、基线与改进后的验证记录；清理确认无用的临时文件。
课程准备、真实运行、你本人完成的练习分别总结；不将这一周表述为一年落地经验。
下一阶段由这一周暴露的真实短板决定，不先扩展成复杂企业系统。
