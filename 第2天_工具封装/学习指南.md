# D2：把 API、数据库和文档封装成工具

[课程首页](../README.md) · [当天学习笔记](学习笔记.md) · [学习进度](../学习进度.md)

本页所有命令都在课程根目录执行，先运行：

```powershell
Set-Location 'H:/论文学习/agent/xuexi'
```

代码在上一层的 `xuexi_lab/`，下面提到的路径均相对于课程根目录。

目标：理解“接口一致、后端不同”。工具都是名称＋说明＋参数＋返回值，内部可能请求 HTTP、查询 SQL 或读取文件。

## 1. 先独立运行（约 45 分钟）

```powershell
./.venv/Scripts/python.exe -X utf8 -m xuexi_lab init
./.venv/Scripts/python.exe -X utf8 -m xuexi_lab tool weather --city '成都'
./.venv/Scripts/python.exe -X utf8 -m xuexi_lab tool expenses --category '差旅'
./.venv/Scripts/python.exe -X utf8 -m xuexi_lab tool documents
./.venv/Scripts/python.exe -X utf8 -m xuexi_lab tool document --name '02_报销材料.md'
```

实际天气取自 Open-Meteo，带日期、Asia/Shanghai、°C 和来源。它是当地今天的最低/最高温预报，不是此刻温度。
支出是虚构数据：差旅两笔共 550.00 CNY；全部六笔共 860.00 CNY。
文档只是工具读取的文本，不会因为写了“执行某命令”就获得指令权限。

## 2. 看工具边界（约 35 分钟）

阅读 `tools.py` 的 `query_expenses`、`read_document`、`get_weather` 及 `build_tools`。

- SQL 用参数查询，模型不能指定任意 SQL 或数据库路径。
- 金额以整数分保存，避免逐笔浮点累积误差。
- 文档只能来自 `data/knowledge`；无法借此读取配置文件。
- 固定城市坐标用于减少地理编码歧义，只支持成都、北京、上海。
- `ok=false` 是失败，`ok=true,count=0` 是成功查询但无记录，两者含义不同。

## 3. 接到 Agent（约 35 分钟）


观察模型是否选对三个工具，以及最终回答是否分别对应 API、数据库和文档的返回值。
当天只读 API 错误，不追求稳定获取某个固定温度，因为预报会变化。

## 4. 你亲手完成的功能（约 60 分钟）

在 `build_tools` 新增一个 `get_average_expense` 工具，仅接受 `category`。
函数内部调用已有 `query_expenses`，根据返回的记录金额和笔数计算平均值；零笔时返回明确的空结果，避免除零。
注册到返回工具列表，并在工具说明写清币种及“虚构教学数据”。

先独立验证：差旅平均 275.00 CNY、办公平均 70.00 CNY、餐饮平均 85.00 CNY。
再让 Agent 用这个新工具回答；保留工具请求和返回值作为证据。
先自己尝试，卡住时把函数和报错交给我，我给提示后再讲参考实现。

## 5. 边界与验收（约 35 分钟）

```powershell
./.venv/Scripts/python.exe -X utf8 -m xuexi_lab tool expenses --category '不存在'
./.venv/Scripts/python.exe -X utf8 -m xuexi_lab tool document --name 'missing.md'
./.venv/Scripts/python.exe -X utf8 -m xuexi_lab tool weather --city '未知城市'
```

解释每次结果是空数据、缺失资源还是输入不支持。HTTP 超时和服务错误可通过离线行为测试检查，无需故意反复请求外部服务。
验收：你能独立增加工具，说明它的输入、返回结构、数据来源及一种失败情形。
